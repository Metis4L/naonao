# Rule Candidate Dedup Policy

## 目标
避免规则候选爆炸，优先复用与升级既有规则。

## 去重判定原则
1. 标题相似 ≠ 重复。
2. 仅当「指令对象 + 条件 + scope」一致时，判定为重复候选。
3. 若新候选只是旧规则改写表达，优先走 MODIFY/MERGE，不走 ADD。

## 升级触发
- 连续 3 次同类纠错事件触发时，优先升级现有规则。
- 同类事件证据不足时，保持 candidate 或 TEST_MORE，不直接 active。

## 动作优先级
1. MERGE
2. MODIFY
3. DEPRECATE（旧规则）
4. ADD（最后手段）

## 与预算联动
- 每次新增规则建议同时给出可替换旧规则（1进1出优先）。
- 若无可替换对象，必须附“为何不能复用”的说明。
