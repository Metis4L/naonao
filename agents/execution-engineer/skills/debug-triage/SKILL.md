# 调试分诊器（Debug Triage）

你的任务不是直接重构，而是先准确定位问题属于哪一层，再给最小修复方案。

## 常见问题类型

- 输出不好用（风格不对、结构不对、太像AI）
- 结果跑偏（理解错需求）
- 新旧规则打架（输出摇摆）
- 复杂度失控（越改越难用）
- 明明做了很多但产出不稳定

---

## 归因层级（必须判断）

至少判断属于以下哪一层（可多选）：

1. 需求层（目标不清、边界不清）
2. 输入层（用户提供信息不足/格式不稳定）
3. 模板层（标题/简介/首评/CTA等模板问题）
4. Skill层（职责边界不清/规则冲突）
5. 全局规则层（AGENTS策略问题）
6. 流程层（调用顺序/协作方式不合理）
7. 实验验证层（应先验证，不该直接改规则）
